## HonoとNext.jsのWebアプリの妥当性

**App Router**では、Server Componentが事前のHonoエンドポイントをfetchで叩く構成は避けるべき。

```
❌ Server Component → fetch("/api/users") → Hono → DB
✅ Server Component → getUsers() → DB
```
同一プロセス内で不要なHTTPホップが入り、シリアライズコストとエラーハンドリング層が増え、fetchのキャッシュの挙動も読みにくくなる。
フォーム送信はServer Actions、クライアント側の更新もServer Actionsで足りる。
**Honoの出番が構造的にない**

Vite React SPA + Hono APIはおすすめの構成で実質のデファクト。
トレードオフは**SSRを捨てる**こと。
SEOがいらない管理画面・SaaSのダッシュボードならもっともコスパがいい。
