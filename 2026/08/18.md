## わかったこと・気づき

今迄CloudFrontはS3から配信される静的ファイルをユーザーの近くのCDNサーバーにキャッシュして、そのキャッシュデータをユーザーに届ける機能だけだと思っていました。
しかし、オリジンはS3だけではかったです。
- ALB / NLB（EC2やECS上のWebアプリ）
- API Gateway, Lambda Function URL
- 任意のパブリックHTTPサーバー
- VPC originsを使えば、プライベートサブネット内のALB/EC2に直接接続ができる

実際の商用システムでは**SPAの静的ファイルはS3**から、`/api/*`はALBから
というようにパスごとにオリジンを振り分ける構成が非常によく使われるらしい。
ユーザーからみればすべて同一オリジンなので、CORS問題も回避できる。

それとCloudFrontは**TTLを0にしてキャッシュを一切しない設定でも、単純に早くなる**
理由は、

- TCP / TLS ハンドシェイクがエッジで終端される。
- エッジ～おオリジン感はAWSのバックボーンを通る
- エッジ～オリジン間のコネクションが再利用される。

この用途を**動的コンテンツアクセラレーション**と呼ぶ。

セキュリティ目的でCloudFrontを置くことも多い。

OAC S3パケットを完全非公開のままCloudFront経由のみ認可


料金面でも**S3から直接インターネットに配信するより、CloudFrontを挟んだほうが安くなるケースが多い**
理由は、AWSのオリジンからCloudFrontへのデータ転送が無料だから。
