## MySQLとPostgreSQLの違い

個人開発でMySQLとPostgreSQLの両方を使っているので、何が同じで何が違うのかを整理しました。

### 共通しているところ

どちらもリレーショナルDBで、SQL、トランザクション、外部キー、B-treeインデックス、`SELECT ... FOR UPDATE` など基本的な道具は同じです。
どちらも**MVCC**（行の古い版を残しておく仕組み）を使っているので、普通の `SELECT` は書き込み中の行でも待たされずに読めます。

CRUDやテーブル設計の考え方はほぼそのまま両方に使えるので、違いは「中の作り」と「書き方の方言」に分かれるという理解です。

### 中の作りの違い

一番大きいと思ったのは、テーブルのデータの並べ方です。

- **MySQL（InnoDB）**：テーブルそのものが主キーの順に並んでいる（クラスタ化インデックス）
- **PostgreSQL**：行は順番を気にせず置かれていて、インデックスがその場所を指している

なので、MySQLでランダムなUUID（v4）を主キーにすると、INSERTのたびにテーブルの途中に割り込むことになって遅くなるそうです。
連番か、時刻順に並ぶUUIDv7を使えばいいらしく、PostgreSQL 18には `uuidv7()` という関数があるらしいです。

古い行の版の置き場所も違って、MySQLはundoログという別の場所に置き、PostgreSQLはテーブルの中に残します。
PostgreSQLの方は残った古い行を **VACUUM** で掃除する必要があって、名前だけ知っていたVACUUMはこのためにあるのだとわかりました。

既定の分離レベルも違って、MySQLはREPEATABLE READ、PostgreSQLはREAD COMMITTEDです。
しかも同じREPEATABLE READでも、PostgreSQLはロストアップデートが起きそうになると後から更新した方をエラーにするのに対して、MySQLはエラーにならずに上書きされるそうです。
名前が同じでも中身が同じとは限らないので、DBを変えるときは注意が必要だと思いました。

### 書き方の違い

普段コードを書いていて引っかかりそうなものをまとめておきます。

| | MySQL | PostgreSQL |
|---|---|---|
| 連番ID | `AUTO_INCREMENT` | `GENERATED ALWAYS AS IDENTITY` |
| 入れたIDを取る | `LAST_INSERT_ID()` | `INSERT ... RETURNING id` |
| UPSERT | `ON DUPLICATE KEY UPDATE` | `ON CONFLICT ... DO UPDATE` |
| Goのプレースホルダ | `?` | `$1, $2` |
| 真偽値 | 中身は `TINYINT(1)` | 本物の `boolean` |
| UUID型 | ない | ある |

気をつけたいと思ったのは次の3つです。

- MySQLは既定の設定だと**大文字と小文字を区別せずに比較する**（`'A' = 'a'` が真になる）
- MySQLの `utf8` は3バイトまでしか入らないので、絵文字を入れるなら `utf8mb4` にする
- MySQLは `ALTER TABLE` を実行するとその時点で勝手にコミットされる。PostgreSQLはDDLもロールバックできるので、マイグレーションが途中で失敗しても元に戻せる

## テーブル設計の基本

テーブル設計で気をつけることも簡単に聞きました。

- 同じ情報を2か所に持たない（正規化）。注文テーブルにユーザー名をコピーせず `user_id` で参照する
- 主キーは意味のない値（連番やUUIDv7）にして、メールアドレスのように変わりうる値は `UNIQUE` にする
- 基本は `NOT NULL` にして、NULLは「値がないこと」に意味があるときだけ許す
- ルールはアプリ側だけでなく、外部キーや `UNIQUE`、`CHECK` でDBにも守らせる
- 金額は `FLOAT` ではなく `DECIMAL` か整数で持つ
- 多対多は中間テーブル（`user_tags(user_id, tag_id)` など）で表す

意外だったのは外部キーとインデックスの関係です。
MySQLは外部キーを張るとその列にインデックスを自動で作ってくれますが、PostgreSQLは作ってくれないので、自分で張らないとJOINや親の行の削除が遅くなるそうです。
PostgreSQLを使っているのに知らなかったので、今のテーブルを見直したいと思いました。
