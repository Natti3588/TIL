# 2026-11-20

## AIの記憶を整理する「Dreaming」

参考: [AI も「一晩寝かせる」と考えがまとまる 寝ている間に記憶を整理する Dreaming の仕組み](https://qiita.com/KYoshiyama/items/623e13ced9c119b614aa)

### Dreamingとは

Dreamingは、AIが昼間の作業ログを夜のうちに読み返し、間違ったメモを直したり、わかったことをWikiにまとめたりする処理です。
Anthropicが2026年11月に公開した記事「The components of agent memory」で紹介されました。

人間は寝ている間に、その日の出来事を整理して記憶に組み込むと考えられています。
Dreamingはこれと同じことを、ログという原本を見返しながら行います。
原本が残っているので、メモが正しいかどうかを答え合わせできるのが人間との違いです。

### 記憶の4つの層

AIの記憶は次の4層に分けて考えます。

1. ログ（作業の記録そのもの）
2. 記憶メモ
3. 整理した記憶（Wiki）
4. 毎回読むコンテキスト（Claude Codeでいう CLAUDE.md や MEMORY.md）

Dreamingは下の層をもとに上の層を直し、4層目に何を載せるかを選び直します。
4層目は毎回読み込まれるので、小さく保つことが大事です。

Claude Codeには1・2・4層目にあたる機能はありますが、3層目のWikiと夜のDreamingはまだないので、使うなら自分で作る必要があります。

### Dreamingがすること

- **メモを直す**: 「締め日は25日」と覚えていても、翌日の会議で「11月分から月末」に変わったら、その夜にログと照らして書き換えます。
- **Wikiを育てる**: 約35万ファイルの社内文書で試した実験では、検索だけだと正答率53%、Wikiと検索を組み合わせると61%に上がりました。

### うまく使うコツ

- Wikiが効くのは、複数の資料をまたいで答える質問です。1つの資料で答えが済む質問なら、検索だけで足ります。
- Wikiは膨らませないようにします。元の資料より大きくなったWikiは、何も要約できていません。
- 覚え方を細かく縛るより、「何のために覚えるか」という目的を伝えるほうが成績が上がりました。
- Wikiを作る役は分けます。資料ごとに事実を書く係（並列）、重複をまとめてリンクを直す係（1人だけ）、Wikiを読んで答える係（読み取り専用）に分け、朝に人が差分を確認します。

小さいモデルでもWikiを使えば、大きいモデルが生の文書を検索するのとほぼ同じ精度で、料金は約15分の1で答えられたそうです。
夜に整理しておけば、昼は安く答えられるということです。

### 筆者がClaude Codeで試した結果

筆者は `claude -p`（対話せずに1回だけ実行するモード）でDreamingを自作し、架空のチームの4週間分のログ（約24万字）を1日ずつ19晩かけて整理させました。

- 締め日やリリース日の変更は、新しいログをもとにWikiが書き換えられました。
- 書き足すだけだとWikiはログの0.78倍まで膨らみましたが、最後に棚卸しをすると0.36倍まで縮みました。
- 資料をまたぐ質問9問では、正答率がログだけで89%、Wikiとログで95%になり、読み込むトークンも36%減りました。
- 1週間分のログで試したときは差が出ませんでした。Wikiが効くのは、ログが一度に読み切れない量になってからです。
